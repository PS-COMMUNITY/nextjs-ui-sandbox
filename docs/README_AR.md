# PC Repair 3D Studio — دليل المشروع (الإصدار 2.0.0)

مختبر صيانة حاسوب افتراضي ثلاثي الأبعاد تعليمي، بواجهة عربية كاملة (RTL)، يتيح للطالب فكّ وتركيب مكونات الحاسوب داخل هيكل افتراضي، مع سلاسل سلامة إلزامية، وتشخيص POST، وفاحص توافق، ومحاكاة SMART، ومهام موجهة واختبارات وتقارير.

> **تنبيه تعليمي:** كل المحتوى والأرقام داخل التطبيق تعليمية توضيحية للمنصة المرجعية (LGA1700 / DDR5 / ATX) وليست مرجعًا فنيًا لصيانة أجهزة حقيقية. المحتوى يحتاج مراجعة معلم التخصص (موثّق في حقل `sourceNote` لكل مكوّن بالكتالوج).

## التقنيات

| الطبقة | التقنية |
|---|---|
| الإطار | Next.js 16 (App Router) — تطبيق صفحة واحدة SPA بكل الشاشات داخل مسار `/` واحد |
| اللغة | TypeScript (وضع strict — `tsc` نظيف) |
| الرسوميات | Three.js 0.186.1 — مشهد إجرائي بالكامل بلا أي ملفات GLB خارجية |
| الواجهة | Tailwind CSS 4 + shadcn/ui + lucide-react |
| إدارة الحالة | zustand |
| الحفظ | localStorage محليًا (مفتاح `pcrs_v1_state`) + تصدير/استيراد JSON و CSV |

## الميزات (10 شاشات)

1. **الرئيسية** — بوابة تعريفية مع اختصارات انتقال سريعة.
2. **المختبر 3D** — مشهد ثلاثي الأبعاد إجرائي (270 mesh / ~8000 مثلث): تحديد بالنقر، إبراز أخضر، بطاقة معلومات متزامنة، أشعة سينية (X-Ray)، عرض تفجيري، كاميرا قابلة للتدوير والتقريب، صينية قطع للقطع المفكوكة.
3. **كتالوج القطع** — 12 مكوّنًا موثقًا: الدور، المواصفات المرجعية، خطوات الفك والتركيب، الأعطال، السلامة، ملاحظات التوافق.
4. **التدريب الموجه** — مهام بخطوات تتحقق آليًا من حالة المحاكاة (مثل مهمة «السلامة أولًا») مع تقدم حي وتوست إتمام.
5. **التجميعة والتوافق** — فاحص توافق من 9 قواعد ثابتة المعرف + تقدير طاقة بهامش إرشادي 30%.
6. **التشخيص** — محرك POST حتمي منفصل عن الإقلاع (POWER_OFF / POST_FAIL / POST_PASS_BOOT_WARNING / POST_PASS_BOOT_OK) وسيناريوهات أعطال جاهزة.
7. **الطاقة والتخزين** — محاكاة SMART بثلاثة سيناريوهات حتمية (healthy / aging / failing) بشارة «محاكاة تعليمية» بارزة.
8. **الدروس والاختبارات** — اختبار من 12 سؤالًا بدرجة ومراجعة تفسيرية وحفظ النتائج.
9. **التقارير** — إحصاءات الجلسة + توصيات + جدول أحداث + تصدير CSV حقيقي (UTF-8 مع BOM للعربية في Excel).
10. **الإعدادات** — جودة الرسوميات (low/medium/high)، الثيم، تصدير/استيراد النسخ الاحتياطي JSON، ومنطقة الخطر (تصفير).

سلسلة الفك الكاملة لكل قطعة مطبقة منطقيًا (مثال GPU): إطفاء ← فصل كهرباء ← فتح غطاء ← فصل كابل طاقة ← فك براغي ← تحرير مزلاج PCIe ← إزالة ← انتقال متحرك إلى صينية القطع. ومحاولات التشغيل بقطع ناقصة تُرفض برسائل تعليمية (مثل: «أول قطعة ناقصة: قرص M.2»).

## المتطلبات

- Node.js 20+ أو Bun 1.x (طُوِّر في هذه البيئة بـ Bun).
- متصفح حديث يدعم WebGL2 (Chrome / Edge / Firefox حديث).
- **لا حاجة بإنترنت وقت التشغيل داخل التطبيق**: التطبيق يعمل كاملًا مع حجب الخدمات الخارجية (تم اختباره مع حجب خطوط Google — الخط يرجع إلى بدائل النظام).

## التشغيل محليًا

```bash
# بـ Bun (البيئة التي طُوِّر بها المشروع)
bun install
bun run dev          # منفذ 3000 — http://localhost:3000

# أو بـ npm
npm install
npm run dev
```

## بناء الإنتاج

`package.json` يعرّف بناء Standalone:

```bash
npm run build   # next build + نسخ static وpublic إلى .next/standalone
npm run start   # تشغيل .next/standalone/server.js
```

> ملاحظة صدق: التطوير والاختبار في بيئة هذا المشروع تمّا في **وضع dev فقط**؛ لم يُنفَّذ بناء إنتاج داخل هذه البيئة (انظر `docs/TEST_REPORT.md`).

## حل المشكلات

| المشكلة | السبب المحتمل | الحل |
|---|---|---|
| «متصفحك لا يدعم WebGL…» وتعطّل المشهد | تسريع العتاد معطل أو متصفح قديم | فعّل تسريع العتاد في إعدادات المتصفح، أو استخدم متصفحًا حديثًا. يمكنك أيضًا خفض جودة الرسوميات من الإعدادات |
| الحفظ لا يعمل / رسالة فشل الحفظ | الوضع الخاص في المتصفح أو مساحة localStorage ممتلئة أو حجب localStorage | أغلق الوضع الخاص، أو أفرغ مساحة، أو صدّر نسخة JSON من الإعدادات واحتفظ بها يدويًا. فشل الحفظ لا يُسقط التطبيق — يبقى العمل في الذاكرة |
| الخط العربي يظهر بخط بديل | خط Tajawal يُحمَّل من Google Fonts CDN وقت العرض | يتطلب اتصالًا بالإنترنت عند أول تحميل؛ بدونه يعمل التطبيق بخطوط النظام دون كسر أي وظيفة (اختُبر ذلك) |
| المشهد بطيء على أجهزة ضعيفة | عتاد رسومي محدود | اختر جودة low من الإعدادات؛ الهدف التصميمي 30fps لكنه لم يُقَس على عتاد حقيقي (انظر TEST_REPORT) |

## تنبيه أمني وخصوصية

هذا التطبيق **لا يجمع أي بيانات ولا يرسل شيئًا إلى أي خادم خارجي**. كل الحفظ محلي في متصفحك عبر `localStorage` (حالة المحاكاة، سجل الأحداث، درجات الاختبارات، الإعدادات)، وكل تصدير (CSV/JSON) يحدث محليًا عبر `Blob` داخل المتصفح. لا حسابات، لا تتبع، لا تحليلات.
